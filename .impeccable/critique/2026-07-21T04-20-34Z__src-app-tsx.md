## Anti-Patterns Verdict

**LLM assessment:** Not slop — a real design system implemented with unusual token discipline (violet neutral ladder, flat tonal layering, dashed inline-add signature, true-inversion dark theme). What betrays it at the edges: (a) first-run empty state is two sentences in a void — no demonstration of the drag/rollup/inline depth PRODUCT.md says should "sell by demonstration"; (b) every task row carries 4 always-visible action icons + a purple avatar chip, contradicting DESIGN.md's hover-reveal spec; (c) dead Search/Sort buttons rendered as live chrome; (d) seed person "Self" wears the accent purple, colliding with the One Voice iris.

**Deterministic scan (detect.mjs):** 43 findings on `src` (3 warning, 40 advisory); markup-only scan clean (exit 0). True issues after false-positive triage: (1) **2rem area-header family** (App.css:298/305/329/713) — violates DESIGN.md's Small Display Rule (1.43rem cap); verified in source. (2) layout-transition on `.project-row-progress-fill` width (App.css:793) — real but negligible on a 90px fill. (3) Four popover shadows use warm-tinted rgba(43,34,24,…) — off the Single Hue Family Rule. (4) Sub-label sizes 0.7–0.75rem below the documented Label step — minor drift. False positives: side-tab (blockquote in user markdown), overused-font (Inter mandated by One Family Rule), sync-badge low-contrast overlay hit (detector failed to composite translucent bg; real ≈5.0:1), radius literals inside calc(), modal backdrop + drag-lift shadow (both verbatim documented in DESIGN.md).

**Visual overlays:** Injected detect.js overlay ran in-page on empty + populated dark-theme views; reported layout-transition, the (false-positive) sync-badge contrast hit, and a transient clipped-overflow flag on .app-shell (not reproduced; likely the overlay itself). Live-server started on :8400 and stopped cleanly.

## Overall Impression

The shell is trustworthy — a Linear/Things-fluent user would sit down and trust the typography, theming, and inline editing immediately. The failures are finishing failures: dead chrome, invisible keyboard surface, no undo, a first-run that shows nothing, and contrast values that contradict the AA claim. The single biggest opportunity: the app is most emotionally careful where data is at risk and least careful where motivation is at stake — completion, the core dopamine loop, is an anticlimax.

## What's Working

1. **Inline-first editing is fully realized** — dashed inline-add at every creation point, titles as auto-growing editable textareas, Shift+Enter spawns a focused sibling (TaskList.tsx:104-110). Things-grade, as promised.
2. **Destructive-action hygiene** — ConfirmModal names entity + full cascade consequence; armed two-step ConfirmButton resets on timeout/Esc. Exemplary error prevention.
3. **Token fidelity** — density knob rescales the whole app (12/14/16px root verified), dark theme is a true inversion with lifted accent, 2px accent focus outline present on all 14 traced Tab stops including hover-revealed actions.

## Priority Issues

- **[P1] Dead Search and Sort buttons in every pane tab bar.** MainPane.tsx:515-523 render both with no onClick; clicking does nothing (verified in source). Dead chrome teaches the user the app lies — and it's the first thing a power user reaches for. **Fix:** remove until implemented, or wire Search now. **Command:** $impeccable distill (or harden).
- **[P1] WCAG AA contrast failures on core text.** ink-muted #9b96ae = 2.59:1 on canvas / 2.85:1 on surface; "Synced" badge (success on success-bg) = 2.24:1 — fails even the 3:1 large-text bar, on the canonical local-first badge PRODUCT.md features. **Fix:** darken muted toward ~#76718c; badge text to a deeper emerald (~#047857 on #d1fae5 ≈ 4.6:1); re-check all four badge states both themes. **Command:** $impeccable colorize.
- **[P2] Task-row chrome overload + accent collision.** Every row persistently shows due-date, person, add-subtask, delete icons + purple "S" avatar; seed person "Self" uses accent purple — the loudest repeated element is a second iris. Violates hover-reveal spec and One Voice rule. **Fix:** adopt the existing `.section-row` reveal-on-hover/focus-within pattern for all task rows; recolor Self off the violet family. **Command:** $impeccable quieter.
- **[P2] No undo anywhere.** Completion instantly removes the row; deletes final. Tombstones already exist in the data layer (data/tombstones.ts). For a whole-life app, one mis-drag is unrecoverable. **Fix:** 5s undo toast for complete/delete built on tombstones. **Command:** $impeccable harden.
- **[P2] No aria-current on selected navigation.** Sidebar rows/Inbox carry no aria-current; accessible names polluted with "(drag to reorder)" on every row (Sidebar.tsx:121). **Fix:** aria-current="page" on selected row; move drag hint to aria-describedby or the drag handle. **Command:** $impeccable audit.

## Persona Red Flags

**Alex (keyboard-first GTD power user):** Shift+A is his only shortcut and it's invisible — no legend, no ⌘K, no j/k, no keyboard complete. Keyboard drag is wired (KeyboardSensor) but undiscoverable. Completing tasks gives zero momentum feedback; count pill unchanged. Search/Sort dead. Verdict: trusts the polish, abandons over the missing keyboard surface.

**Sam (keyboard-only + screen reader + contrast):** Focus outlines excellent (14/14 stops). But no aria-current; muted text 2.6:1 and Synced badge 2.24:1 fail the AA claim; every area row announces "(drag to reorder)"; prefers-reduced-motion unimplemented anywhere in src/ despite PRODUCT.md's promise; due-date popover clipped past right viewport edge. Verdict: skeleton is AA-serious, finishing is not.

**OmniFocus/Things refugee (project-specific):** Depth is real — sub-areas, breadcrumbs, rollups, drag-to-nest all work. But counts never distinguish open from done (cleaned area still reads "4"); DESIGN.md's 40%-dim empty areas didn't render (data-dim="false" on a zero-task area); first-run offers no import/sample structure; no undo in a 6-deep tree. Verdict: structure sells, trust features don't close.

- TinyBase Inspector pink square renders in product UI (App.tsx renders `<Inspector />` unconditionally) — dev chrome in the product surface.

## Questions to Consider

1. If completion is the core dopamine loop, why does the count pill read the same before and after? What should "done" feel like?
2. Why ship dead Search/Sort chrome instead of hiding unreleased capability — what does the first broken click teach?
3. Should "Self" exist as a visible person in a solo app — and why is its color the One Voice accent hue?
4. If the product sells by demonstration, why is first run empty instead of a 3-task "Welcome" area that demonstrates drag, inline edit, and sync?
5. Tombstones already exist — what is the real cost of a 5-second undo toast, and what does its absence say to someone trusting the app with their whole life?
